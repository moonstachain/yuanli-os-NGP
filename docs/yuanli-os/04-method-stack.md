## 1｜IPO 统一信息底座（v4）

来源：`cbm-osa-ipo-map-kit/methodology/unified-information-engine-v4.md`

```
I · 信息采集：全 / 真·一手 / 细
→ P · 信息处理：碎片 → 特征 → 观点 → 洞察 → 全局最优
→ O · 信息输出：闭环 → 自动化 → 智能化
↺ 隐藏回流：输出进入执行，现实反馈成为下一轮 I
```

**重要的版本裁决**：v4 明确**取代**了 v1 的「OSA = 三个 IPO」递归解释。
任何仍按"OSA 是三层嵌套 IPO"理解的内容都已降权，不得再用于定义本体关系。

P 层那条链就是 `os-yuanli` 的策略层次阶梯，也就是下面的信息 5 层。三处命名的对应关系：

| IPO 的 P 层 | `os-yuanli` 策略阶梯 | `info-5l` 五层 |
|---|---|---|
| 碎片 | 数据 | L1 碎片 raw |
| 特征 | 特征 | L2 特征 feature |
| 观点 | 观点 | L3 观点 viewpoint |
| 洞察 | 洞察 | L4 洞察 insight |
| 全局最优 | 全局最优 | L5 单 / 框架 dan |

**这三者不是三套语法，是同一套东西的三种使用形态**：IPO 是能力底座定位，`os-yuanli` 是策略 gate 内嵌的判断式，`info-5l` 是可独立调用的诊断式。

## 2｜信息 5 层完整定义

来源：`os-yuanli-info-5l`（**已于 2026-07-27 归档，继任仓 `yuanli-strategy-trilogy`**）
起源：2026-04-22 HAY 与涛哥的「信息 5 层」商科方法讨论

### 五层

| 层 | 别名 | 定义 |
|---|---|---|
| **L1 碎片** | raw | 原始未加工素材（资料、笔记、截图、对话、搜索堆）。密度低、噪音高、无命名归类 |
| **L2 特征** | feature | 打标签、分类、分层、分维度。**结构化但无判断**——不说哪个好、为什么 |
| **L3 观点** | viewpoint | **有态度、有判断、有倾向**，能推荐/反对/选择。内部再分 **L3 低**（万能正确话）与 **L3 高**（场景化观点） |
| **L4 洞察** | insight | **观点的观点**——一组观点里能捅灭其他所有观点的那一个。**去掉它方案会塌** |
| **L5 单 / 框架** | dan | **能稳定复现洞察的方法**。E=mc² 级紧凑度，≥3 个不同场景可复用 |

> **AI 最爱停在 L2。** 这是这套方法最重要的一条经验判断。

### 判层原则

按层定义词典逐条匹配，**取最低命中层**（保守估计，避免高估）。

**L2 糊弄词典**（出现这些词，很可能只到 L2）：`top N` / `分 N 类` / `N 大维度` / `A/B/C 类`

**L3 低警报句式**（有判断但没解释为什么）：`要 + 动词 + 抽象名词` / `……是关键` / `核心是……`

### 跃迁提问

| 从 → 到 | 代表提问 | 难在哪 |
|---|---|---|
| L1 → L2 | 「能归出哪几类？」「3 个维度概括？」 | — |
| L2 → L3 | 「你建议用哪 1 个？为什么？」 | **难在敢判断** |
| L3 低 → L3 高 | 「换到具体场景还成立吗？」 | **难在给具体场景** |
| L3 高 → L4 | 「只能保留 1 条是哪条？」「哪条能捅灭其他观点？」 | **难在找到捅灭其他的那条** |
| L4 → L5 | 「有什么方法能稳定产出这种洞察？」「换 3 个场景还成立吗？」 | **难在找到足够通用的 3+ 场景** |

### L4 洞察的验真句式（内心自问）

```
去掉这一条，整个方案会塌            → 是洞察
去掉其他观点都不会塌                → 确认真洞察
有 aha 感                          → 候选
觉得「对但没那么厉害」              → 只是 L3 高
```

L4 需同时具备：**反直觉 · 可证伪 · 去掉会塌**。

### L5 单的验真清单（5 项全满足）

1. 有名字（短、上口）
2. 有公式或结构（一行或一图）
3. ≥3 个不同场景稳定出好洞察
4. 去掉单，效果明显下降
5. 他人听一次就能复用

### 「炼丹」的精确含义

「炼丹」**不是**泛指 AI 生成，而是有确定操作定义：

| 项 | 内容 |
|---|---|
| 触发 | `/wuceng --deep`（full mode） |
| 输入 | 已层析过的对话 / 报告 / AI 产出 |
| 产出 | `insight_candidates`（含 insight、reason 捅灭了哪些观点、falsifiability、aha 度）+ `dan_candidates`（含 name、formula、≥3 reusable_scenarios、evolution_hook） |
| 材料不足时 | 诚实声明"材料不够，需要 XXX"，**不硬凑** |
| 出单后 | 询问固化位置（个人 playbook / 团队炼丹手册 / 新 skill）；累计 3+ 次复用可升为 protocol 级 |

### 三条 Guardrail

1. **默认只给跃迁提问，不替用户思考。** `--deep` 才是显式邀请出洞察。
2. **不收尾不到 L4。** 报告/方案类产出，用户说"完成/发布"时强制层级检查（除非明确豁免）。
3. 关键词自动提示：检测到 `top N` / `分 N 类` / `N 大维度` 就提醒可能停在 L2。

## 3｜OSA 决策合同

来源：`osa-strategy-card-distiller`（Agent 工作流）+ `cbm-osa-ipo-map-kit`（v2 机器合同与评分引擎）

结构：`OSA = O × S × A`，沿 **能力域（横轴） × 三责任层（纵轴）** 铺开，一格一卡。

三责任层的两套等价命名：

| 中文 | 英文 | 含义 |
|---|---|---|
| 战略层 | **Direct** | 定方向，靠人脑关键判断 |
| 管控层 | **Control** | 控系统，确保不翻车 |
| 执行层 | **Execute** | 做动作，可自动化流水 |

> 注意：这套「战略/管控/执行」是 **CBM 责任轴**，与 `os-yuanli` 的「主题层/策略层/执行层」（工作OS 三层 gate）**不是同一个东西**，只是中文里都有"执行层"。按 YPORT4-G0 第 3 节，四条轴允许映射但禁止互相替代。

### 七道质量门（含 Python 脚本 `osa_card_quality_gate.py`）

单论断 · 备选淘汰 · L4/L5 层级 · 数字回 truth_source · 多源互证 · 双轴定位 · trust 校准

### 反模式：倒沙漏 / fan-out

**战略卡数量 > 执行卡数量 = 假聚类。** 正常的信息漏斗应该是 fan-in（收敛），倒沙漏说明没有真正提纯。

### 诚实纪律

- 口语数字标注 `(口语待核)`，**不推算**
- `va = min(想, 自)`；无 `gold_attest` 金卡的项封顶 4 分——**无金卡不虚报**
- 公式默认值 `⚪` 不能冒充真据 `🟢`；authored 叶必须带证据句

## 5｜前置追问层：七窍玲珑

来源：`qiqiao-linglong`

**定位**：用最少的提问把人类意图的信息量榨到最大，再收敛到唯一一条承重主线。
产物是「**意图规格 + 主线骨架**」，交棒给写作/执行 skill 或人，**不自己写最终成品**。

**招牌判断**：

> 收敛的全局最优 = **镜像主人隐性方法**，不是 AI 自创的通用最优。

### 硬约束：最多 3 轮

- 每轮 = 结构化批量提问（带编号、带推荐项）
- 跨过"大致懂你要什么"的置信阈值 → **立即停止**开始收敛
- 满 3 轮必须停；**越过 3 轮 = 违约**
- 一次性环境：合并为一个编号清单一次问完

### 四步流程

```
Step 0 预解析（零提问）  对七窍逐个评置信，能推断标 [推断]，不能标 [待问] 并估信息增益
Step 1 提问              按信息增益降序打包 [待问]；增益 = 影响权重 × 不确定度
Step 2 收敛              二八砍长尾 → ≤3 条承重结论 + 一条贯通主线（钩子→意义→落点）；AI 兜底处标 [兜底]
Step 3 意会回放（强制）   念回意图规格，问「这条线对吗、哪儿拨」——确认后才产出
```

### 七窍

| # | 窍 | 探什么 |
|---|---|---|
| 1 | 意图窍 | 真目标与成功标准 |
| 2 | 主窍 | 主人 vs 受众 |
| 3 | **法窍**（招牌） | 从"最满意的一次成功样本"反解隐性方法 |
| 4 | 落点窍 | 不可再退的落点 |
| 5 | 约束窍 | 时间盒 / 篇幅 / 渠道 / 禁忌 |
| 6 | 收敛窍 | ≤3 承重结论 + 贯通主线 |
| 7 | 验窍 | 意会回放确认 |

### 与相邻 skill 的分工（不重叠，可串联）

| skill | 做什么 | 何时用 |
|---|---|---|
| `intent-grounding` | 把模糊需求**压缩成 objective** | 任务开头 |
| `qiqiao-linglong` | 意图探求 + 镜像主人方法 + 主线收敛 | 目标模糊但有暗线时 |
| `brainstorming` | 发散候选 | 任务中段 |
| `wuceng-distill`（info-5l） | 层析现有信息 + 给跃迁提问 | 讨论没深下去时 |

典型链：`七窍玲珑（前置）→ intent-grounding/objective → 执行 skill`，讨论卡住时插入 `wuceng-distill`。

**不适用**：意图已明确的一次性执行（"把这段改成 snake_case"）→ 直接做。

| CBM 四门 + H/V/A/E | 4+4 | `cbm-osa-ipo-map-kit` | 究竟/完备/递进/原子，引擎 `--check` 强制 |

**共性模式**：格式门（必要不充分）+ 质量门（决定高低）+ 机器 heuristic 脚本 + 人工 human-confirmed 封顶。

### 信息密度的核心信念

> **信息量 ≠ 信息密度。**
> 信息量 = 单位面积塞了多少数据（堆 100 个指标 → 信息量高）
> 信息密度 = 每 token 携带的决策价值（一行字 → 一个 actionable insight）
> 厉害的 dashboard 是后者。

### 防失真护栏清单

| 护栏 | 机制 | 出处 |
|---|---|---|
| D3 不确定性显式化 | N=几、边界、未验证假设、±X% 必须写在页面上 | dashboard / mckinsey / hybrid（**强制**） |
| 倒沙漏检测 | 战略卡 > 执行卡 = 假聚类 | osa-distiller |
| 无金卡不虚报 | 无 `gold_attest` 封顶 4 分 | cbm-osa-ipo-map-kit |
| 公式 ⚪ 不能冒充 🟢 | authored 叶必须带证据句 | cbm-osa-ipo-map-kit |
| 数字默认存疑 | 口语数字标 `(口语待核)`，不推算 | osa-distiller |
| 事实边界 | 策略推断 vs 可核验事实分离 | ai-risk-value-proof `governance/FACT_BOUNDARY.md` |
| Phase 1 防捏造门禁 | 私有材料 ≥5 锚点，否则声明"基于公共认知" | hybrid-expert-brain |
| Producer 不可见 private weights | 防执行端被 outcome 污染 | recursive-capability-architect |

### N 值标注惯例

| 标注 | 含义 |
|---|---|
| `N=1` | 仅一例贯穿实证，每次使用都视为 dry-run / 评估 |
| `N=2` | 跨域第二例验证 |
| `N=3 Verified` | 第三例后才允许去掉试验标签、正式 skill 化 |
| `🟢 / 🟡 / ⚪` | 真据 / 推断 / 公式默认 |

## 8｜克隆体实验的版本差异（值得记住的一个坑）

`clone-alpha`（原力OS 首个 `internal_colleague` 克隆体，母体 V18）的 **DNA 三条**是：

```
递归进化 · 技能统帅 · 人类友好
```

而 `os-yuanli` kernel 的**治理OS 三条线**是：

```
递归进化 · 全局最优 · 人类友好
```

**第二条不一样**：克隆体版是「技能统帅」（不替代专业 skill，但要给出最小充分组合），kernel 版是「全局最优」。

这不是笔误，而是两个不同版本/语境的产物——克隆体面对的问题是"别抢专业 skill 的活"，kernel 面对的问题是"别做局部最优"。
**引用治理三线时必须说明用的是哪个版本**，不要混着说。

同理，评分尺也有两把互不兼容的：

| 尺 | 维度 | 出处 |
|---|---|---|
| 6 轴 × 5 检查点 = 30 点 | 主题/策略/执行/递归进化/全局最优/人类友好 | `os-yuanli/references/audit-rubric.md` |
| 10 维 D1–D10 | 战略对齐/执行质量/闭环率/workflow 复用/反馈质量/自治水平/漂移频率/skill 利用/人类边界尊重/进化贡献 | `clone-alpha/clone-state/clone-scorecard.json` |
| 12 维 × 10 = 120 分 | 信息密度 rubric | `high-info-density-dashboard-designer` |

三把尺服务三个对象（任务成熟度 / 克隆体健康度 / 交付物密度），不要互相换算。

## 9｜术语可见性说明

两个子代理对 21 个公开仓做了全量 `grep`。结论：

| 术语 | 公开仓可见性 |
|---|---|
| `原力OS` / `os-yuanli` / `验真` / `进化` / `失真` / `炼丹` / `洞察层` / `全局最优` | ✅ 广泛出现 |
| `六判断` | 仅 3 处（`clone-alpha` / `os-yuanli-info-5l` 引用），战略类 11 仓**全部未出现** |
| `主题层` / `执行层` / `治理OS` / `工作OS` | **仅存在于 `os-yuanli-share-max` kernel**，其余仓库全部未出现 |

**含义**：工作OS 三层 gate 这套语言基本没有扩散到 skill 生态，生态里实际通行的是「质量门 + rubric + N 值标注 + 失真护栏」这一套。
所以如果要让 Agent 生态真正按三层 gate 运行，需要显式注入，不能假定 skill 仓库里已经有了。
