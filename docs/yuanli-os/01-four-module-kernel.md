## 1｜四模块（C1–C4）主脊柱

四模块不是四个页面，也不是四个文件夹，而是**一条必须闭合的环**。

```
C1 文脉 ──▶ C2 大脑 ──▶ C3 地图 ──▶ C4 链路 ──▶ LRN ──▶ Task2 REUSE
  Who/Why    Evidence     Bottleneck   WPK/ACT/OUT   Learning     ▲
  Boundary   Memory       DEC                                      │
                                                                   └── 回流至 C2
```

### C1｜一纸文脉（Wenmai）

| 项 | 内容 |
|---|---|
| 第一性问题 | 我是谁？为什么做？什么不能做？谁有权决定？ |
| 管理对象 | Identity / Intent / Taste / Boundary / Authorization |
| 运行输出 | `CTX`｜Minimum Necessary Context |
| 编译式 | `Principal × Current State × Task × Authority → CTX` |
| 皇冠句 | **主权归人，智能归系统调用。** |

关键约束：C1 **不是**保存所有资料，而是在任务到来时把长期宪法与当前现实编译成**最小必要 CTX**。
模型能力增强 **≠** 法权自动扩大。

### C2｜一个大脑（Epistemic / Memory Core）

| 项 | 内容 |
|---|---|
| 第一性问题 | 我们已经知道什么？凭什么相信？过去发生过什么？哪些已经过期？ |
| 管理对象 | Evidence / Knowledge / Memory / Evaluation |
| 成熟判据 | `Recall → Use → Writeback → Recall Again` |
| 皇冠句 | **Memory ≠ Retrieval。查到了不代表是真的；记住了不代表这次该用。** |

六层记忆结构（原力健康 OS2.0 的实现样板）：

| 记忆层 | 内容 | 后台要求 |
|---|---|---|
| 事实记忆 | 正式检查、长期连续数据 | 来源、时间、Freshness、Provenance |
| 情境记忆 | 工作负荷、旅行、睡眠等背景 | 避免脱离 Context 解读指标 |
| 决策记忆 | 当时为什么选这个 DEC / WPK | 保留替代方案与未知 |
| Outcome 记忆 | 现实后来发生了什么 | Outcome ≠ Attribution |
| Learning 记忆 | 什么规则值得保留 | 必须 grounded in OUT |
| Evolution Lineage | 成功、失败、被替代版本 | Positive + Negative Memory 都留 |

**重要区分**：`原力大脑`（Yuanli Federated Brain，跨 C1–C4 的联邦智能架构）**≠** `C2 一个大脑`（其中的认知记忆核心）。层级是：

```
原力OS → 原力大脑（Federated Brain）→ C2 一个大脑 → GBrain / Retrieval Projection
```

`GBrain / Vector / Graph / HTML` 都是 **可重建的 Serving Projection**，不得自行晋升 Canon。

### C3｜一张地图（Policy State）

| 项 | 内容 |
|---|---|
| 第一性解释 | **Policy State｜战略/选择状态** |
| 正典模块名 | 仍然是 `C3｜一张地图`（不得改名） |
| 当前权威本体 | **CBM｜事业能力操作模型** |
| 边界 | Capability Registry / Router / AI Planner / Decision Engine 可以**增强** C3，但**不能自动取代 CBM** |

C3 不是百科，是**当前瓶颈地图**，把复杂问题组织成三类：

1. **Primary Battle**｜当前唯一主战役
2. **Guardrails**｜不能被主战役破坏的边界
3. **Clinical Queue**（领域化命名）｜必须由专业权威关闭的问题

**CBM 六个不可拆原语**（所有战略页面必须映射到其中之一，不得另造平行战略语法）：

| # | 原语 | 含义 |
|---|---|---|
| 1 | Component | 稳定能力身份 |
| 2 | State | 主体在特定时间的当前能力状态 |
| 3 | Heat | 差距/约束/机会形成的**稀疏**战略热区 |
| 4 | Battle | 经 Human DEC 晋级的**有限 WIP** 战役 |
| 5 | Tradeoff | Pause / Defer / Stop / Reallocate — **没有代价就不叫战略** |
| 6 | Reality / Reuse | 结果经现实裁决且在后续真实场景改变行为，才构成复利 |

CBM 只有三种合法输出：**Route** / **Prioritize** / **Frame Tradeoff**。
CBM 非法输出：自动诊断人生、自动决定 Battle、自动执行动作、自动把 Outcome 晋级为 Learning、因页面更新改写 Canon、把领域事实吸收进 Strategy Soul。

| 皇冠句 | **Output ≠ Action ≠ Outcome。** |

C4 的终点**不是 Done**，而是 Task2 的行为改变。

## 2｜八段主链｜CTX → EVD → DEC → WPK → ACT → OUT → LRN → Reuse

这是整个体系的**运行时**，也是唯一被承认的复利路径。

| 段 | 全称 | 判据 |
|---|---|---|
| `CTX` | Context | 目标、角色、边界、授权 |
| `EVD` | Evidence | 允许相信的证据包 |
| `DEC` | Decision | 为什么选这条路线、替代方案、停止条件 |
| `WPK` | Work Package | 被授权的工作包 |
| `ACT` | Action | 现实中**真正发生**的动作 |
| `OUT` | Outcome | 世界真实给出的结果 |
| `LRN` | Learning | 从结果提炼出的下一次候选规则 |
| `Reuse` | Reuse | Learning 在**后续独立任务**前被调用，并真实改变判断或行动 |

### 每个 Gate 的防伪规则

```
DEC ≠ 建议列表      → 必须形成当前优先级
WPK ≠ ACT           → 方案、提醒、AI 输出都不是行动
ACT ≠ OUT           → 做了，不代表有效
OUT ≠ Attribution   → 变化发生，不代表知道为什么
LRN ≠ REUSE         → 保存经验，不代表未来真的用上
REUSE ≠ Compounding → 一次复用还不是多代复利
```

### 硬停机条件

```
NO REAL QUESTION      → NO OS RUN
NO VERIFIED ACT       → NO VALIDATED OUT
NO OUT                → NO STRONG LRN
NO DISTINCT TASK2 REUSE → NO COMPOUNDING
NO REUSE              → NO RSI
```

## 3｜复利的两级证明门

这是判断"系统是否真的变强"的唯一标准，不能用页面数、Memory 条数、Tool 调用次数替代。

### Atomic Proof

```
Learning preload → Task 2 → DEC / WPK / ACT 真实改变
= SECOND_TASK_REUSE_PROVEN
= Atomic Compounding Proof
```

含义：**过去第一次真正进入了未来。**

### System Proof

```
多次独立复用 + Outcome 持续改善 + 适用边界清楚 + 过期能识别 + 负迁移受控
= COMPOUNDING_AT_MEANINGFUL_SCALE
= System Compounding Proof
```

成熟度阶梯（原力健康 OS2.0 的当前刻度，可作为通用参照）：

| 级 | 名称 | 状态 |
|---|---|---|
| L1 | Governed Intelligence | 可运行 |
| L2 | Reality Operating | 可运行，Human-gated |
| L3 | Compounding Intelligence | 等待 FIRST_REUSE 严格结算 |
| L4 | Recursive Evolution / RSI | 未解锁 |

## 6｜三 Surface 法权矩阵

冻结总式：**One OS × Three Surfaces × One Reality Loop × One Human Sovereign**

| 能力 | GitHub | Notion | Website |
|---|---|---|---|
| 定义 / Constitution / Contract | **Authority** | Projection | Projection only |
| Component Ontology / Registry | **Authority** | 人类可读投影 | 不暴露技术层 |
| 当前私人 State | Pointer / governance only | **Native Human Runtime Master** | 禁止公开 |
| Battle / Tradeoff / Human DEC | Contract / receipt / audit | **Human Decision Surface** | 只展示公共案例 |
| Reality facts | Evidence pointer / receipt | Adjudication / human view | 仅 public-admitted outcome |
| Publication | Release contract | Editor / review surface | **Public rendering only** |

Projection Lifecycle（禁止再说"两个平台互相同步"）：

```
Canon Change:   GitHub PR → Human Gate → Merge → Canon Revision
                → Projection Delta → Notion / Website rebuild → Projection Receipt
Runtime Change: Reality / Human observation → Notion State / Runtime
                → Evidence binding → Human adjudication → governance receipt
Decision Change: CBM Heat → Candidate → Human DEC → Battle → Tradeoff → C4 action path
Learning Change: Outcome → Attribution → Candidate Learning
                → later-context Preload → behavior changed → Reuse Receipt → eligible promotion
```

**没有 last-write-wins；没有 projection 自动晋级 Canon；没有 AI 自动确认 Decision / Learning / Reuse。**

7. CBM 是 C3 kernel，不是超级数据库。
8. Domain facts 保留 federated authority，不被 Life CBM 吞并。
9. Candidate ≠ Decision；Decision ≠ Action；Action ≠ Outcome。
10. Outcome ≠ Learning；Learning ≠ Reuse；Reuse 必须是 later distinct context 的真实改变。
11. Privacy partition 在检索与路由前执行，不靠 UI 隐藏。
12. 没有 receipt / evidence / human gate，不允许宣称 PASS、Reality、Learning、Reuse 或 Compounding。

## 11｜Agent 工作守则（我在这套体系里该怎么做事）

1. **先判法权，再做检索。** 任何事实主张先问：这属于 T1–T5 哪一类？当前 authority 是谁？freshness 能否证明？
2. **默认最小充分 Context。** 多拿一个 Estate 就属于非最小 Context。
3. **不把 Projection 当 Truth。** Notion 页面、GBrain 检索结果、HTML 看板都不是真源。OB 不可达时不能拿 GitHub LLM-Wiki 的 committed history 冒充当前语义 Canon。
4. **区分 Output / Action / Outcome。** 我交付了文件 ≠ 现实动作发生 ≠ 有效果。
5. **不自动晋级。** 我可以提 Learning Candidate，不能宣称 Canon 变更、不能宣称 PASS / Reality / Reuse / Compounding。
6. **主权归人。** 涉及发布、客户触达、正式知识变更、资金、健康、权限，先做 Authority Check。
7. **每轮留下可消费物。** 不能只交付结论，要留下下一轮能直接调用的东西。
8. **显式声明 Gap。** 拿不到就说拿不到（fail-closed），不画绿。
